The run file (.h5): what it holds

One run file per tracking run, tra001.h5 next to the calibration cal001. It is the raw record: every recorded frame's tracking result and motor readings, the segments and recordings, every event, and the metadata (devices, run, the .cal used). The .tra files are exported from it (Save the traces) and hold only the tracked rows.

When the data reach the disk

  • The file is created when tracking starts (beads selected, camera running) and opened at the first Record on; frames are written only while recording is on.
  • Writing is in real time, not at Save: rows wait in memory for at most flush_s = 1 s or flush_frames = 150 rows, then go to disk (root attributes flush_s, flush_frames, frames_written). A crash loses at most the rows since the last flush; closed_cleanly = 0 then says so and a reader uses frames_written rows.
  • Record off ends a recording interval; the file stays open. It closes when the camera stops, at Reset calibration or a new bead selection, or when the program ends; the close writes end_utc, frame_rate_hz and closed_cleanly = 1, and the sidecar tra001.meta.json (the /metadata group as JSON without the .cal copy (cal_bytes, stack), for a quick look without HDF5).
  • Save the traces (.tra) reads this file and writes LabVIEW's tra001-000, tra001-001, ... (one per 2,000,000 rows) next to it: frame, magnet mm, rotor deg, x y z per bead; dropped and tracking-error rows left out. The .h5 is not changed by the export.
  • Lost beads: x, y, z = -1 (the LabVIEW marker); bead_lost = 1. Force is not a column: the magnet position is stored raw (magnet_mm, the last read-back before each frame, ~10 per second) and the force follows from the calibration recorded in /metadata/devices/magnet/force_calibration_at_start (the motor_reading events carry force_pN per reading).
