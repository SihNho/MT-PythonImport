런 파일(.h5)에 담기는 것

추적 한 번에 런 파일 하나, 보정 파일 cal001 옆의 tra001.h5. 원본 기록입니다: 기록된 모든 프레임의 추적 결과와 모터 읽기값, 세그먼트와 녹화 구간, 모든 이벤트, 메타데이터(장치, 런, 사용한 .cal). .tra는 이 파일에서 내보내며(Save the traces) 추적된 행만 담습니다.

데이터가 디스크에 쓰이는 시점

  • 파일은 추적이 시작될 때(비드 선택, 카메라 동작 중) 만들어지고 첫 Record on에 열립니다. 프레임은 녹화가 켜진 동안만 기록됩니다.
  • 쓰기는 Save 때가 아니라 실시간입니다: 행은 메모리에 최대 flush_s = 1초 또는 flush_frames = 150행까지만 머물다 디스크로 갑니다(루트 속성 flush_s, flush_frames, frames_written). 프로그램이 죽어도 마지막 flush 이후 행만 잃고, closed_cleanly = 0이 그 사실을 알리며 읽는 쪽은 frames_written행만 씁니다.
  • Record off는 녹화 구간만 끝내고 파일은 열린 채입니다. 카메라 정지, Reset calibration, 새 비드 선택, 프로그램 종료 때 닫히며, 닫을 때 end_utc, frame_rate_hz, closed_cleanly = 1과 사이드카 tra001.meta.json(/metadata 그룹을 JSON으로, .cal 사본(cal_bytes, stack)은 제외; HDF5 없이 빠르게 보기용)을 씁니다.
  • Save the traces (.tra)는 이 파일을 읽어 LabVIEW의 tra001-000, tra001-001, ... (2,000,000행마다 하나)을 옆에 씁니다: frame, magnet mm, rotor deg, 비드별 x y z; 드롭된 행과 추적 오류 행은 제외. 내보내기는 .h5를 바꾸지 않습니다.
  • 잃어버린 비드: x, y, z = -1(LabVIEW 표식), bead_lost = 1. 힘은 열이 아닙니다: 자석 위치를 원본 그대로 저장하고(magnet_mm, 각 프레임 직전의 마지막 읽기값, 초당 약 10회) 힘은 /metadata/devices/magnet/force_calibration_at_start에 기록된 보정으로 구합니다(motor_reading 이벤트에는 읽기마다 force_pN이 있음).
